## 2. P1（公開前に修正すべき）

### P1-1 数値入力欄が、キー入力の途中で値を書き換えてしまう（全シミュレーター・株式ラボ共通）
- 該当: `src/components/NumField.tsx` の `onType`。キーを押すたびに `set(snapToStep(n, min, max, step))` で範囲内へ丸めている。親の `value` が変わると `useEffect([value])` が下書き（`draft`）を消すため、入力途中の値が丸めた値で上書きされる。
- 再現（Playwright、キーを1文字ずつ入力して実測）:
  - DCF の WACC（min 3）に「12」と入力すると **15** になる（「1」→3に丸め→表示が「3」→「2」を足して「32」→上限15）。
  - レバレッジの参入価格（min 1,000）に「50000」と入力すると **10,000,000** になる。
  - 先頭の数字が最小値より小さい値は、キーボードでは正しく入力できない。WACC では10〜15%（先頭の「1」が最小値3未満）が該当し、参入価格（最小値1,000）では先頭の1桁が必ず1,000に丸められるため、ほぼすべての値が該当する。
- 影響: iPhoneではスライダーで細かい値を合わせにくく、数値欄での入力が主な手段になる。誤った入力値のまま計算結果が表示されるため、P1とした。
- 既存テストで検出できなかった理由: `tests/numfield.test.ts` は純粋関数 `snapToStep` だけを検証している。`e2e/audit-round2.mjs` は `fill()` で値を一括設定するため、1文字ずつの入力を再現しない。
- 修正案: 入力中は範囲内の値のときだけ `set` を呼び、範囲外は下書きのまま保持して欄の近くに「範囲 min〜max」を表示する。丸め（クランプ）は blur／Enter の時点で行う。回帰テストは Testing Library の `userEvent.type` で「12」「50000」を1文字ずつ入力するケースにする。

### P1-2 暗号資産の申告分離課税（20%）が成立済みであるのに、制度データが「確認済みの改正はない」と表示している
- 該当: `src/content/regulations.ts` の REG-CRYPTO-TAX（keyNumbers「申告分離課税の適用: 現行制度では適用されない（制度データとして確認済みの改正はない）」、history「確認できる一次資料がないため登録していない」）、`docs/DECISIONS.md` D6、教材 I-04。
- 確認できた現況（2026-11-03 検索）:
  - 令和8年度税制改正による改正所得税法は **2026年3月31日に成立・公布**された（令和8年法律第12号）。
  - 暗号資産のうち「特定暗号資産」の譲渡等による所得を **20%（復興特別所得税を含め20.315%）の申告分離課税**とする。適用開始は、暗号資産を金融商品取引法の対象とする改正法（金融商品取引法及び資金決済に関する法律の一部を改正する法律）の**施行日の属する年の翌年1月1日以後の譲渡等**。
  - 前提となる金融商品取引法等の改正法は、2026年7月23日に官報で公布されたとする解説がある。施行日を定める政令については未確認。開始は2028年1月とする見方が多い。
  - 対象は「特定暗号資産」に限られ、それ以外（海外取引所・DEX経由等の扱いを含む）は引き続き総合課税とされる。損失の3年間繰越控除は分離課税の対象分に限られる見込み。
- 根拠の強さ: 上記は主に税理士法人・法律事務所の解説（例: 辻・本郷税理士法人、長島・大野・常松法律事務所）と、検索で得た要約による。**一次資料（財務省「令和8年度税制改正の解説」、e-Gov法令の改正所得税法・租税特別措置法、金融庁の公布資料）での条文確認は未了**。修正時には一次資料で条文・適用日を確認すること。
- 影響: 「改正はない」という記述は現時点で誤り。学習者に重大な誤解を与えうる制度情報であるため、P1とした。
- 修正案: REG-CRYPTO-TAX の現行（雑所得・総合課税）は維持する。そのうえで `status: 'enacted-not-yet'` の新しい版を追加し、成立日、適用条件（金商法改正法の施行日の属する年の翌年1月1日以後）、対象（特定暗号資産）、税率、繰越控除を登録する。施行日が未確定であることは明示し、推測の日付は入れない。I-04 の概要・誤解・関連問題、D6 も更新する。

### P1-3 こどもNISA（2027年1月開始、成立済み）が制度データに未登録
- 該当: REG-NISA-2024（appliesTo「日本に住所を有する18歳以上の個人」）、教材 M-01。
- 確認できた現況: 2026年3月31日成立の税制改正法により、NISA口座開設の年齢制限を撤廃し、**2027年1月から18歳未満がつみたて投資枠を利用可能**になる（年間投資枠60万円、非課税保有限度額600万円）。18歳到達後は通常のNISAのつみたて投資枠へ移行する。引出し要件は旧ジュニアNISAより緩和される（12歳以降に一定の条件で引出し可とする解説あり）。根拠は大和総研（2026-05-26）等の二次資料で、一次資料（金融庁NISA特設サイト・改正租税特別措置法）での確認は未了。
- 影響: 2か月後に施行される成立済みの改正であり、現行データの対象者記述が2027年1月に陳腐化する。
- 修正案: REG-NISA に `enacted-not-yet`（effectiveFrom 2027-01-01）の版を追加する。つみたて投資枠の対象商品の拡大など、同じ改正に含まれる他の項目も一次資料で確認したうえで登録する。

### P1-5 「専門理論」層が大学レベルとして浅く、株式・暗号資産の重要論点に欠落がある
- 実測: 56教材の理論層は147〜317字（大半が170〜240字）で、式1本と前提1〜2文で構成されている。例: E-02 の理論層はフィッシャー方程式の近似式のみで、A-02 と実質的に同じ水準。E-03 は本文（詳細層）に債務動学（r−g）を書きながら、理論層には期待仮説の分解式しかない。
- 欠落の例（全教材データを語句検索して0件だったもの）:
  - マークル木（Merkle tree）
  - 楕円曲線／ECDSA（デジタル署名の数理）
  - プット・コール・パリティ
  - テイラー・ルール
  - GARCH などボラティリティの時系列モデル
  - p値
  - 米国会計基準（US GAAP）とIFRS・日本基準の違い（要件C「会計基準の違い」）
  - 二重課税（外国株式の配当課税の論点）

  このほか、要件H「時系列分析」は自己相関への言及が2か所あるのみ。
- 第4.2部は、専門理論層に「数式、理論上の前提、実証的な限界、計算例、応用方法」を求めている。現状の理論層は、このうち数式と前提の一部しか満たしていない。株式（B〜D）と暗号資産（G〜I）は各分野4教材（計24教材）で、「特に詳しく」という要件に対して量が不足している。
- 修正案: 株式・暗号資産から優先し、理論層を「式（導出の要点）／前提／実証的な限界（学説の位置づけ・証拠の強さ）／計算例への接続」の4要素で拡充する。上記の欠落論点は、新規教材または既存教材の理論層に追加する。

### P1-6 正答選択肢が「最も長い選択肢」である割合が高く、問題の弁別力を損なっている
- 実測: 単一正答216問のうち、正答が最長の選択肢である問題は **133問（61.6%）**。4択で無作為なら約25%になる。「最も長い選択肢を選ぶ」だけで6割強が正解できる。
- 参考: 元データの正答位置も偏っている（b が103/216）。ただし表示時のシャッフル後は 55/46/65/50 に分散しており、位置の手がかりは解消されている。
- 修正案: 長さが正答の手がかりにならないよう、誤答選択肢にも限定条件や理由を付けて長さをそろえるか、正答を簡潔にする。`tests/content.test.ts` に「正答が最長である比率が一定以下」という検査を追加する（閾値の例: 40%以下）。

### グラフ・表示

- **P2-5 グラフに軸目盛り・軸ラベル・単位がない**（`components/Chart.tsx`）。表示されるのは「最大」「最小」の2つの文字列だけで、横軸（年・利回り・原資産価格・日付）が読み取れない。375px幅では SVG の viewBox（640）が縮小され、**文字の高さは実測5px**で判読できない（1280px幅では21px）。さらに `figure` の既定余白（左右40px）が狭幅で幅を削っている。
  - 修正案: 横軸の目盛り3〜5点と単位、縦軸の単位を描画する。文字は CSS の px で指定するか、コンテナ幅に応じて viewBox を変える。`figure { margin: 0 }` とする。
- **P2-6 DCF の「初年度FCF」は実際には基準年（0年目）のFCF**。`fcfs[i] = fcf × (1+g)^(i+1)` のため、1年目に割り引かれるFCFは105（既定値）である。ラベルを「直近（基準年）FCF」に改めるか、計算を `(1+g)^i` に改める。表示値 1,713.1億円は、現行の定義では Python の独立計算（1,713.13）と一致した。
- **P2-7 株式分割の「保有株数」は発行済株式数を表示している**（既定値で「保有株数 20,000,000株」）。「発行済株式数」に改めるか、保有株数の入力欄を設ける。
- **P2-8 ポートフォリオのシミュレーター名が「効率的フロンティア」なのに、グラフは配分ごとのボラティリティだけ**（横軸は配分、縦軸はボラティリティ）。リスク（横軸）とリターン（縦軸）の散布図として描くか、名称を改める。
- **P2-9 AMM の「価格インパクト」に手数料0.3%が含まれている**（既定値で9.3%、手数料を除く純粋な価格インパクトは9.09%）。一般的な用法（手数料を別に示す）と異なるため、両者を分けて表示する。「取引後プール価格 0.827」には単位（出力トークン／入力トークン）がない。
- **P2-10 NISA比較で、生涯枠1,800万円を超える条件でも結果の近くに警告が出ない**（例: 月30万円×40年＝元本1.44億円）。超過時は結果の直後に短い警告を出す（第3.3部「結果を著しく変える制度上の適用条件」）。また、税率0.20315と枠（360万円・1,800万円）がUIの文字列とコードに直書きされており、AGENTS.md の「制度情報は regulations.ts で管理」に反する。

### 制度・教材

- **P2-11 復興特別所得税の課税期間の記述が陳腐化**。REG-STOCK-TAX の history「復興特別所得税は2037年まで」について、令和8年度改正（2026-03-31成立）で税率が2.1%から1.1%に下がり、課税期間は**2047年末まで延長**された。あわせて**防衛特別所得税（基準所得税額の1%）が2027年1月から課税**される。上場株式等の合計税率20.315%は変わらないが、2027年以降は内訳が変わる（所得税15%＋復興特別所得税約0.165%＋防衛特別所得税0.15%＋住民税5%。内訳の数値は計算上の値で、一次資料での確認は未了）。一次資料は国税庁「防衛特別所得税及び復興特別所得税に関するQ&A」（令和8年5月）、財務省「令和8年度税制改正の解説」。成立済み・未施行の版として登録し、教材 M-03 の内訳表記も2027年以降の注記を加える。
- **P2-12 実在の過去データが一切ない**（DECISIONS D7 によりライセンス上の理由で見送り）。要件「過去の実在データと架空データを区別して使用する」のうち、実在データ側が未充足。`kind: 'historical'` の型は存在するが未使用。公開利用条件が明確な公的統計（日本銀行の時系列統計、FREDなど）を候補として、ユーザーの判断が必要。
