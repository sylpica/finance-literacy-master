# DECISIONS.md — 仮決定の記録

| # | 決定 | 理由 | 影響 |
|---|------|------|------|
| D1 | 新規リポジトリで開発（既存の fp-master 等は変更しない） | 指示書はFP試験対策化を禁止しており、既存FPアプリとは目的が異なる。既存作業領域に同種プロジェクトは存在しなかった（Phase 0調査、2026-11-02） | リポジトリ作成はGitHub側の権限確認後に実施。ローカル開発を先行 |
| D2 | 技術スタック: React 19 + TypeScript + Vite、状態保存は IndexedDB（自前ラッパー）、PWAは vite-plugin-pwa | 指示書の推奨構成に一致し、ユーザーの他アプリ（fp-master）と保守方法を揃えられる。Dexie等の追加依存を避け、保存層を小さく保った | スキーマ変更時は db.ts の DB_VERSION と移行を更新すること |
| D3 | ルーティングはハッシュルーティング、Vite base は './' | GitHub Pagesのサブパス配信で、リポジトリ名に依存せず深いURLのリロードでも404にならない | URLに # を含む |
| D4 | ルーター/状態管理ライブラリを追加しない | 画面数が限られ、自前実装で十分。小さな依存は保守性とバンドルに有利 | 画面追加時は App.tsx の分岐を拡張 |
| D5 | 制度の調査基準日は指示書どおり2026-10-24を起点としつつ、実装時の一次資料（金融庁・国税庁、確認日2026-11-02）で数値を再確認 | 指示書 §13 の指定と「開発時に最新を再確認」の併記に従う | NISA枠・20.315%・暗号資産の雑所得区分は確認済み一次資料に基づく |
| D6 | 暗号資産の税制について、申告分離課税化などの改正動向は制度データに登録しない →（2026-11-03 改定）令和8年法律第12号の成立を財務省の法律案要綱で確認したため、REG-CRYPTO-TAX-SEPARATE を「成立済み・未施行」として登録。適用開始日は施行政令が未確認のため登録しない | 成立は一次資料で確認できた。施行日は政令に委ねられており、推測の日付を入れないため | 施行政令が公布されたら effectiveFrom を設定し、適用開始後に in-force へ切り替える |
| D7 | 実在企業の過去事例ケースは収録せず、架空ケース＋「過去事例型」の枠組みのみ実装 | 実データの再配布ライセンスを確認できない市場データを公開リポジトリに入れないため（指示書 §4・§12）。仮想投資の採点方式（根拠・リスク評価、時点情報の分離）は実データでもそのまま使える設計 | 実データケースは、利用許諾を確認できるデータセットが得られた時点で追加可能 |
| D8 | 問題数は固定せず、カバレッジマップ（全56教材×2問＝112問）を先に確定して配置 | 指示書 §5「初期完成版の問題数は固定しない。先にカバレッジマップを作る」に従う | COVERAGE.md で論点→教材→問題の対応を管理 |
| D9 | 習熟度は「記憶確率」と呼ばず、難易度重み＋初見正答を重視する説明可能な推定として表示 | 未検証の値を科学的に確定した記憶確率として表示しない指示書 §6 のため | UI・分析画面に推定方法を明記済み |
| D10 | モンテカルロ等の乱数はシード固定（mulberry32）で再現可能にする | 指示書 §7 の再現性要件 | シード・試行回数・分布仮定をUIに表示 |
| D11 | 清算価格・スリッページ等、取引所/プロトコル固有の厳密式が存在しないモデルは「教材用の近似」と明示して実装 | もっともらしいが不正確なモデルを正確な結果として提供しないため | 各シミュレーターに前提・限界を表示 |
| D12 | 数式表示はプレーンテキスト（「式: …／変数: …／条件: …」）とし、KaTeXを導入しない | オフライン容量と保守を優先。数式の意味（変数・単位・条件）はテキストで完全に表現できる範囲に教材を限定 | 複雑な数式が必要な教材が増えたら再検討 |
| D13 | 監査（2026-11-02）を受け、表記を統一: 計算式中の等号・コロンは全角（＝／：）を基本、問題文は常体、金額は原則「万円」表記、主名称は「順序リスク（シーケンスリスク）」 | ファイルごとに表記が混在すると学習者の読み取り負荷と誤読リスクが上がるため | 今後のコンテンツ追加でも同じ規則を適用する |
| D14 | 出典粒度の改善は「実在を確認できた一次資料だけ」で行う: 株式税制は国税庁パンフレット「株式・配当・利子と税」、iDeCoは国民年金基金連合会の公式サイトを具体出典として追加（確認日2026-11-02）。理論系教材の所管機関トップページへの紐付けは残る項目がある | 架空URLの追加は禁止事項。未確認の詳細ページを足すより、確認済みの具体資料へ段階的に差し替える方が正確性に適う | 理論系の出典具体化は、原典（論文・公式文書）を確認できた教材から順次行う |
| D15 | PWAアイコンはSVGのみとし、PNG 192/512 は見送る | 配信手段（push-files）がUTF-8テキスト前提でバイナリを扱えず、PNGを入れると配信自体が成立しないため。SVGアイコンは主要ブラウザで表示可能 | バイナリを配信できる手段が得られたらPNGアイコンを追加する |
| D16 | 間隔反復のパラメータ上限を明示仕様化: ease は 1.3〜2.8、間隔は最大365日 | 監査で上限なしが指摘されたため。無制限の ease 上昇は復習間隔を不当に伸ばす | srs.ts のコメントと実装を一致させ、回帰テストで固定 |
| D17 | 制度データの effectiveFrom は「適用開始」と言える日付にのみ使う。公表日・加入拡大等の節目の日は announcedAt に分離し、意味は history に明記する | 国税庁の公表日（2017-12-01）や iDeCo の加入拡大日（2017-01-01）を施行日と表示するのは事実誤認になるため | RegulationsPage は announcedAt を「公表日・節目」として表示する |
| D18 | PWAの更新方式を registerType 'autoUpdate' に変更（プロンプト方式は受付UIがなく新版が適用されないため） | 監査で、更新待ちのService Workerが永遠に適用されない不具合を確認 | 新版は次回読込時に自動で切り替わる |
