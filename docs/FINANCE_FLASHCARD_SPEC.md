# FINANCE_FLASHCARD_SPEC.md — 単語帳仕様（監査ラウンド3で新設）

実装: `src/content/flashcards.ts`（カード生成）、`src/content/carddefs.ts`（定義・設問文）、`src/pages/FlashcardsPage.tsx`（画面）、`src/store/db.ts` の `cardStates` ストア（永続化）。

## 1. カードデータ

- 生成元: 全56教材の `terms`（重要用語）。カードID は `FC-<lessonId>-<教材内連番>` で、問題ID（Q-…）とは空間を分ける。
- 総数: 332枚（用語スロット332件の全て）。ユニーク用語は311件で、複数教材に現れる用語は教材ごとに別カードになる（文脈が教材に紐づくため）。
- 表 = 用語。裏 = 設問文（cue）＋ 定義文。設問文は「〜を指す用語はどれか」形式で、**用語そのものを含まない**（裏スタートで答えが透けないことを単体テストで保証）。
- 定義文は教材本文を根拠に新規校正したものだけを収録する（`CARD_DEFS`、311用語・51〜105字）。教材内に明示定義があったのは棚卸しで116/332件（34.9%）のみで、残りは本文の記述を根拠に校正した。定義を校正できない用語はカード化しない方針（今回は全用語分を校正し終えたため欠けはゼロ。将来用語が増えた場合は、定義を書くまでカードに出ないことがテストで検出される）。
- 重複用語で定義が相違した16件は全件目視し、意味の矛盾ではなく表現・強調点の差であることを確認のうえ、初出教材の定義を採用した。

## 2. 表／裏の開始方向

- 開始前に「表から開始（用語→定義）」「裏から開始（定義→用語）」を選ぶ。選択は localStorage `flm-card-direction` に保持され、次回も引き継がれるが、開始前に毎回変更できる。
- セッション中も方向切替ボタンで切り替えられる。切替時は現在のカードのまま表示面が変わる（次からではなく今のカードに即時適用される旨を aria-label とボタン文で明示）。
- カード面はクリック／タップ／Enter／Space で反転する（role=button、tabIndex=0）。

## 3. 絞り込み・保存・シャッフル

- 絞り込み: 分野セレクト、教材セレクト、保存したカードのみ（トグル）、自己評価（すべて／未学習のみ／曖昧・覚えていない）。
- 対象0枚のときは理由を示す警告文を表示し、開始ボタンは出ない。
- 開始ボタンには常に対象枚数を表示する（例「332枚で開始する」）。
- カードの☆保存は cardStates.bookmarked に即時保存され、反転操作の領域の外に常設する（反転と誤認しない配置）。
- シャッフルは決定的シード方式: シード文字列から LCG で生成する Fisher–Yates。単語帳・演習共通の `shuffled()` を使い、**集合の要素と件数が不変**であることを単体テスト（置換性）で保証する。
- セッション中の「再シャッフル」は現在のカードを保持し、新しい順序でのそのカードの位置へ移動する（進捗が壊れない）。

## 4. 自己評価と復習（SRS）との関係

- 自己評価は3段階（覚えた／まだ曖昧／覚えていない）で、押すと記録して次のカードへ進む。
- 自己評価は **主観記録として cardStates に分離保存** し、問題演習の attempts や SRS スケジュールには混算しない（画面下部にもその旨を明記）。問題の復習間隔は従来どおり回答の正誤だけで決まる。
- 完了画面: 学習枚数と自己評価の内訳を表示し、「もう一周」「曖昧・覚えていないだけ再学習」「条件を変える」「ホームへ」を出す。

## 5. 永続化

- cardStates は IndexedDB v2 の新ストア（keyPath cardId）。DB移行の詳細は FINANCE_MIGRATION_AUDIT.md。
- バックアップ v2 に含まれ、v1 バックアップからの復元では空として補われる。

## 6. 受入テスト

- 単体: カード総数が全用語スロットと一致、cardId 一意、全カードに定義（30字以上）と設問文、設問文に用語を含まない、教材との domainId/terms 整合、シャッフルの置換性と決定性（tests/flashcards.test.ts）。
- E2E: 表スタート→反転→定義表示、保存トグル、自己評価で前進、再シャッフル後も総数不変、保存のみで1枚、裏スタートで設問文が先・反転で保存した用語が出現（リポジトリE2E項目16系、監査E2E 39+6項目）。
