## 1. 監査方法

- 実ブラウザ監査: Playwright（Chromium）で13ルート×4幅（320/375/768/1280px）＝52組合せ＋対話シナリオを走査し、横はみ出し・JSエラー・文書高さを実測。
- コード監査: QuizPage・データ層・学習分析・SRS・ルーティングを指令書の章立てと対照して読み解いた（読み取り専用）。
- コンテンツ棚卸し: 教材4層・用語・問題232問を実データから集計（FINANCE_CONTENT_VISUAL_AUDIT.md）。
- 区別: 本書の指摘は「実操作・実測で発見」か「コード読解で発見」かを各項目に明示する。

## 3. 修正後の再監査で見つけた問題（収束ループの記録）

再監査（最終ビルドでの全ルートスイープ＋E2E）で新規に3件を発見し、いずれも修正して再検証した:

1. 単語帳の設定画面で教材セレクト（最長オプション623px）が幅320/375で横にはみ出した → CSS で chip-row 内の label/select に幅制約を追加し解消（スイープ再実施で全幅0件を確認）。
2. 図表キャプションに内部実装名（core.ts の関数名）が露出していた → 利用者向けの文言に修正。
3. リポジトリE2Eが新設の開始前画面に対応しておらず失敗した（アプリの退行ではなくテスト側の陳腐化） → E2Eを開始前画面経由に改訂し、単語帳・保存した問題の項目を追加（51/51 PASS）。
